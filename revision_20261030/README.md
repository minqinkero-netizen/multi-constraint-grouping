# 空间与多轮任务约束下的资源分组优化（2026-10-30修订）

本目录对应修订稿中的数学模型、四种求解方法和重新运行的实验。旧稿材料仍保留在仓库其他位置；复现本稿以本目录及论文附录指定的提交为准。论文 PDF 和 Overleaf 排版包单独提供，运行代码不需要 LaTeX。

## 模型与方法

输入为资源坐标、管理者数、容量上限、组内距离上限、逐轮目标及重要轮次名单。资源唯一分配，分组在所有轮次固定；每名管理者每轮最多启用一个本组目标。重要轮次必须全部完成，其他轮次最小化等权目标遗漏。

距离使用组内直径，容量上限为5，允许不满和空组。资源可以跨轮重复调用，不模拟烟花的一次性消耗。本次未取得官方亮度及工业损失的完整定义，本目录采用本文定义的等权遗漏目标。

固定分组后每组每轮最少遗漏为 `max(c_tg - 1, 0)`。代码求解消去启用变量后的替代模型；P1仅作为原始规则的检查依据，不调用P1优化，不比较P1/P2的数值结果。

| 简称 | 实现 |
| --- | --- |
| G | 多起点受约束贪心：优先安排可选组最少的资源，允许组中比较新增遗漏和组大小 |
| LS | 受约束构造后，用可行移组及交换严格减少遗漏 |
| MIP | SciPy `milp` / HiGHS分支割整数规划，单线程，`mip_rel_gap=0` |
| LPR | HiGHS对偶单纯形LP；最大分量取整；容量调整；随机冲突移组/交换修复；必要时LP引导重构 |

所有方法每输入的最大计算进程用时均为600秒，另保留实际退出和最终复核耗时。提前完成、达到工作量上限或停滞条件时可提前停止。外部监控终止尚未返回的求解器时，不能从其内部取出尚未传回的候选；这类结果保留为空，不冒充不可行证明。

LPR的取整只先保证唯一分配，不自动保证容量或任务约束。每次运行分别保存松弛分量、初次取整、修复情况和最终检查。

## 实验协议

性能实验采用两类位置分布 U/C，参数为 `(n,m,T)=(80,20,16),(160,40,32),(320,80,48)`，每类每套参数3个独立输入，共18输入、72次运行。两类的任务均利用独立保存的可行见证生成，但四种方法不读取见证。

- U：单位正方形中均匀随机点，最近邻生成每组4资源的见证，`r=1.02*见证最大组内距离`。
- C：网格中心周围各生成4点，坐标扰动为 `±0.18*s`，`r=1.35*s`，`s=1/ceil(sqrt(m))`。
- 前一半轮次重要：每见证组以0.55概率贡献一个目标；其他轮次每资源独立以0.25概率成为目标。
- G最多128次构造，LS最多32次；LPR必要重构最多64次。连续12次完成构造未改善时停止，构造失败仍消耗构造次数。
- 冲突修复最多12000步，连续1500步未改善历史最好冲突数时停止；参数和接受概率见 `round_repair.py`。
- 每次运行只使用其随机过程记录，不采用见证初值或其他方法的可行解。
- 同一规模内依次运行各方法；Linux允许不同规模绑定到不同逻辑CPU并行（默认最多2组），每个求解器仍单线程。Windows不使用此绑定，自动顺序运行。已发布的80资源组先单独完成，160与320资源组随后在不同逻辑CPU运行；调度调整前的160资源预备记录保留于 `orchestration/`，不混入72次正式比较。
- `data/protocol.json`记录环境、输入随机种子、线程及参数。`data/*/record.json`记录每例的方法执行顺序。

小算例单独使用3套参数、每套3个独立输入，比较MIP和LPR；另外保留8资源、9资源和32轮说明情境。它们不计入18个性能输入。基础例枚举256个带标签分配，其中32个可行，逐轮恢复遗漏与分组计数逐一核对。

## 安装

安装Python 3.12，在本目录打开PowerShell：

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
$env:PYTHONUTF8="1"
$env:OMP_NUM_THREADS="1"
$env:OPENBLAS_NUM_THREADS="1"
```

Linux/macOS可使用 `python3 -m venv .venv`，后续Python路径为 `.venv/bin/python`。图表需要中文字体；Windows通常已有微软雅黑/宋体，其他系统可安装Noto Sans CJK SC。

## 先核对已有结果（不调用求解器）

```powershell
.venv\Scripts\python analyze_study.py
```

分析器重查输入见证、最终整数分组、逐轮调用、遗漏量以及保存的LP分量。失败记录不会删除。输出：

- `data/summary.json`：按规模/分布、总体、配对与取整阶段统计。
- `data/results_table.csv`：72次逐运行结果，可用电子表格打开。
- `data/audit.json`：逐次核对结论。
- `generated/`：论文表格及基于实际记录生成的文字片段。
- `figures/study_*.png`：输入分布、成功数/耗时和共同可行配对图。

如需直接写入下载的论文排版目录，可追加 `--paper "论文目录的路径"`。绘制概念图运行 `python make_diagrams.py`；同样支持 `--paper`。不重新运行求解就能重建这些图表。

## 求解一个输入

```powershell
.venv\Scripts\python solve_one.py `
  --input solutions/base8_input.json `
  --method LPR --budget 600 --out my_base8_run
```

方法可选 `G`、`LS`、`MIP`、`LPR`。输出目录必须是新的目录，已有同名结果不会覆盖。程序JSON采用零起始数组下标，`groups`/`calls`对外清单采用一起始编号。

## 重新运行全部实验

在仓库副本中，选新的性能结果目录：

```powershell
.venv\Scripts\python run_study.py --out new_data
.venv\Scripts\python run_scenarios.py
.venv\Scripts\python analyze_study.py --data new_data
```

完整计算可能需要数小时。主实验从已完成记录继续；如要重跑小算例，应先在副本中另存 `scenario_data/`。`--budget`非600时属于另设协议，不能把输出作为论文600秒协议的数据。

## 指标与文件

`obj`只对合格分组定义，为实际近似轮次遗漏数；`infeas`对完整整数候选定义，为归属、容量、距离和重要轮次违反量之和。无候选不记为零违反，无可行方案不记为零目标。均值须结合可行数和候选数阅读。计时包括失败运行。

| 路径 | 内容 |
| --- | --- |
| `benchmark.py` | 固定模型、四种方法、统一计时与外部时限 |
| `round_repair.py` | 容量调整及随机冲突修复 |
| `grouping_core.py` | 输入、分组、调用校验与恢复，无P1优化 |
| `solve_one.py` | 用户单例入口 |
| `run_study.py` | 性能输入与72次运行 |
| `run_scenarios.py` | 独立小算例和保留情境 |
| `analyze_study.py` | 已存结果检查、汇总、图表 |
| `plot_style.py`, `make_diagrams.py` | 字体选择与概念图 |
| `data/*/instance.json` | 某独立输入 |
| `data/*/witness.json` | 可行见证，求解方法不读取 |
| `data/*/{G,LS,MIP,LPR}.json` | 单次完整运行与状态 |
| `scenario_data/results.json` | 小算例和说明情境的新记录 |
| `solutions/` | 固定展示方案与输入、操作清单 |

本版本的实测环境和最终数值以 `data/protocol.json` / `data/summary.json` 为准。新的机器可能产生不同限时结果。本目录不含工业验收用例、官方损失实现或官方DLL；论文未进行工业验收。

发布快照的data/results.json与各record.json采用索引形式，完整输入和逐次结果保存在同目录的独立JSON文件。分析程序同时支持索引和完整聚合形式，数值相同。
